# 文字起こしちゃん for Windows

会議の音声を **ネット接続なし・完全ローカル・無料** で文字起こしする Windows 常駐アプリです。

Zoom や Google Meet を開くと自動で録音を始め、会議が終わると自動で文字起こしして Markdown に残します。操作は原則ゼロです。

## 経緯

本プロジェクトは、[minorun365](https://github.com/minorun365) 氏による macOS 版
**[live-dictation（文字起こしちゃん）](https://github.com/minorun365/live-dictation)** を出発点にしています。

> 日本語の会議をローカルで文字起こし・要約し、英語→日本語翻訳にも対応する macOS アプリ

「会議を検知して自動で録音する」「マイクと再生音を別々に取り込んで話者を分ける」「すべてローカルで完結させる」という設計思想は、すべて原作のものです。本実装はそれを Windows に持ち込んだものであり、アイデアの出発点は氏にあります。

原作は Apple のフレームワーク（ScreenCaptureKit / Speech / Translation / FoundationModels）に強く依存しているため、**コードの流用は一切していません。** Swift から C# への移植ではなく、同じ思想を Windows の API で作り直した独立実装です。

| 役割 | macOS 版（原作） | 本実装（Windows） |
|---|---|---|
| 音声取り込み | ScreenCaptureKit | WASAPI（NAudio） |
| 音声認識 | Speech framework | sherpa-onnx + 日本語モデル |
| 発話の区切り | Speech framework | silero VAD |
| 要約・翻訳 | FoundationModels / Translation | **非対応**（後述） |
| 常駐 | メニューバー | タスクトレイ |

原作に敬意を表します。原作・本実装ともに MIT License です。

### 原作との違い

- **要約と翻訳はありません。** 出力した Markdown を Claude などに渡す前提の設計です
- **録音中のリアルタイム表示はありません。** 理由は「設計上の判断」を参照してください
- 話者分離は原作と同じく「音源の違い」で行います（声の聞き分けはしません）

## できること

- Zoom / Teams / Webex / Slack ハドル / Discord / ブラウザ会議を検知して **自動で録音開始**
- **マイク（自分）と再生音（相手）を別々に取り込み**、話者を分けて記録
- 会議終了を検知して **自動で停止 → 自動で文字起こし**
- タスクトレイに常駐。ウィンドウを閉じても検知を続ける

## 動作環境

- Windows 10 / 11（x64）
- .NET 8 デスクトップランタイム
- 初回のみモデルのダウンロードに約 963MB

GPU は不要です。CPU のみで動作します。

## セットアップ

### 1. モデルを取得する

PowerShell で実行してください（約 963MB）。

```
powershell -ExecutionPolicy RemoteSigned -File scripts\download-offline-model.ps1
```

`%LOCALAPPDATA%\LiveDictation\models-offline\` に展開されます。アプリはここを自動で探すため、追加の設定は不要です。

リポジトリの `models\` に置いても構いません。実行ファイルから親をたどって探すため、クローンしたフォルダのまま使えます。
両方にある場合は `models-offline\` が優先されます。1 つのフォルダに複数のモデルを置いた場合は、最後に追加したものが使われます。

### 2. ビルドする

Visual Studio 2022 で `LiveDictation.sln` を開いて実行するか、次を実行します。

```
dotnet build -c Release
```

### 3. 動作確認する

```
dotnet run --project src\LiveDictation -- --selftest
```

音声デバイスとモデルの読み込みを確認し、結果を `%LOCALAPPDATA%\LiveDictation\selftest.txt` に書き出します。

> **マイクの許可を確認してください。**
> `設定 → プライバシーとセキュリティ → マイク` で「マイクへのアクセス」と、
> 一番下の **「デスクトップアプリがマイクにアクセスできるようにする」** を両方オンにします。
> 後者がオフだと、録音も会議検知も動きません。

## 使い方

起動するとタスクトレイに常駐します。あとは会議を始めるだけです。

| トレイアイコン | 状態 |
|---|---|
| 灰色の輪郭 | 待機中 |
| 赤い丸 | 録音中 |
| 黄色の輪郭 | 文字起こしモデルが未設定（録音はできます） |

手動で録りたい場合は、ウィンドウかトレイメニューの「録音を開始」を押してください。

### 画面の見方

録音中はウィンドウに入力レベルが出ます。**3 つの情報で「ちゃんと録れているか」が分かります。**

| 表示 | 分かること |
|---|---|
| `OK` / `取得できず` | デバイスを掴めているか |
| `12.3 秒受信` | 音が流れてきているか（**無音でも増えます**） |
| レベルバー | どれくらいの音量か |

マイクによっては無音時に完全な無音データを返すため、バーが動かないことがあります。その場合は **受信秒数が増えているか** を見てください。増えていれば正常です。

録音を停止すると文字起こしが始まり、進捗バーが出ます。1 時間の録音でおよそ 4 分です。

### ヘッドホンを使ってください

話者の区別は **声の聞き分けではなく、音の取得経路** で行っています。スピーカーで相手の声を流すと、その音がマイクにも入り、自分の発言としても記録されます。

### 保存先

```
%LOCALAPPDATA%\LiveDictation\Sessions\<日時>\
├─ transcript.md    文字起こし ← これを使います
├─ microphone.wav   自分の声（16kHz モノラル）
└─ system.wav       相手の声（16kHz モノラル）
```

外部に送信する処理は含みません。

## 自動録音の条件

| 対象 | 開始の条件 |
|---|---|
| Zoom / Teams / Webex / Slack / Discord | マイクを使い始めたら |
| Chrome / Edge / Firefox | マイクと再生の **両方** が動いているとき |

ブラウザで両方を見るのは、録音サイトや音声入力ツールを会議と誤判定しないためです。

### 停止の条件

**開始と継続で条件を変えています。**

```
開始 … マイクを掴んだ（ブラウザは再生も）        ← 厳しく
継続 … マイク または 再生 のどちらかが生きている ← ゆるく
```

マイクの解放は、**ミュートと退出のどちらでも同じように観測されます。** マイクだけを見ていると、ミュートして聞き役に回っただけで会議終了と誤判定してしまいます。会議中は相手の声が鳴り続けるので、継続の判定には再生も含めています。

| 状況 | マイク | 再生 | 判定 |
|---|---|---|---|
| 会議中・自分が話す | ○ | ○ | 継続 |
| 会議中・ミュートで聞き役 | ✕ | ○ | 継続 |
| 退出 | ✕ | ✕ | 終了（猶予後） |

- 両方が消えてから **60 秒** 経過で停止します（`MeetingGraceSeconds`）
- 手動で始めた録音は会議アプリの状態では止まりません。**3 時間** で自動停止します
- 退出後も同じブラウザで動画などを再生していると止まりません。困る場合は `KeepMeetingAliveWhilePlaying` を `false` にしてください

マイクの使用状況は、次の 2 つの **どちらかで拾えれば使用中** と判定します。

1. **オーディオセッション**（WASAPI）: 録音デバイス上で State が Active なセッション
2. **ConsentStore**（レジストリ）: `LastUsedTimeStop` が 0 なら使用中

当初は 2 だけで判定していましたが、**Chrome はマイク使用中でも ConsentStore が更新されないことを実機で確認した** ため、1 を主たる信号として追加しています。

## 設定

### 画面から変えられるもの

| 項目 | 場所 |
|---|---|
| 録音と文字起こしの保存先 | メイン画面の「保存先」右の **変更** ボタン |
| 会議検知による自動録音 | メイン画面のチェックボックス |

保存先は、選んだフォルダに**実際に書き込めるかを確かめてから**適用します。
書けない場所（権限が無い、読み取り専用）は拒否します。存在の確認だけでは、
フォルダが見えても書けない場合を弾けないためです。

変更は**次の録音から**適用されます。録音中に書き込み先を変えると音が欠けるため、
動いている録音はそのまま元の場所に保存されます。これまでのセッションも移動しません。

> OneDrive やネットワークドライブを指定すると、録音中の書き込みが
> 同期や通信で止まり、音が欠けることがあります。

### 設定ファイル

`%LOCALAPPDATA%\LiveDictation\settings.json`（無ければ既定値で動作）

画面から設定を変えた時点で、**全項目が書かれたファイルが作られます。**
以降は下の表の項目をテキストエディタで直接編集できます。

| 項目 | 既定値 | 説明 |
|---|---|---|
| `AutoRecordEnabled` | `true` | 会議検知による自動録音 |
| `MeetingGraceSeconds` | `60` | 会議終了とみなすまでの猶予（秒） |
| `KeepMeetingAliveWhilePlaying` | `true` | 再生中は会議継続とみなす（ミュート対策） |
| `MaxRecordingHours` | `3.0` | 手動録音の上限 |
| `EnableFinalPass` | `true` | 停止後の文字起こし |
| `OfflineModelDirectory` | `""` | 空なら models-offline\ とリポジトリの models\ を自動探索 |
| `VadModelPath` | `""` | 空なら探索先の silero_vad.onnx |
| `OfflineNumThreads` | `8` | 文字起こしのスレッド数 |
| `VadThreshold` | `0.5` | 発話とみなす確信度 |
| `VadMinSilenceSeconds` | `0.5` | 発話の切れ目とみなす無音（秒） |
| `VadMaxSpeechSeconds` | `20.0` | 1 発話の上限（秒） |
| `SilenceGateDbfs` | `-55.0` | これより静かな区間は文字起こしにかけない（dBFS） |
| `SessionRoot` | `""` | 保存先。空なら %LOCALAPPDATA%\LiveDictation\Sessions（画面から変更可） |
| `Provider` | `cpu` | `cuda` / `directml` も指定可（別途ランタイムが必要） |

## 製品名・社内用語が認識されないとき

製品名や社内用語のような造語は、**どの音声認識モデルも学習していないため原理的に当てられません。** 誤り方は似通うので、置換辞書で直します。

トレイメニューの「置換辞書を開く」から編集できます（実体は `%LOCALAPPDATA%\LiveDictation\replacements.txt`）。

```
# 誤り => 正しい表記
仕分けッター => シワケッター
re:ポカ ?ミル => ポカミル
```

- 1 行に 1 つ。`#` で始まる行と空行は無視されます
- 左辺を `re:` で始めると正規表現になります（置換後で `$1` が使えます）
- 右辺を空にすると、その語を削除できます
- 書き換えは **次回の文字起こしから** 有効です

まず普通に録音し、`transcript.md` に出た実際の誤りを見てから追記するのが確実です。

## コマンドライン

| コマンド | 用途 |
|---|---|
| `--selftest` | 音声デバイスとモデルを確認する |
| `--record [秒数]` | GUI なしで録音 → 文字起こしまで通す |
| `--watch [秒数] [--probe]` | 会議検知が何を見ているかを表示する |
| `--finalize <パス>` | セッションフォルダ、または音声ファイル単体を文字起こしする |

`--finalize` は m4a / mp3 / wav を受け付けます。会議の録音に限らず、手元の音声ファイルにも使えます。

```
LiveDictation.exe --finalize "C:\path\to\recording.m4a"
```

録音が残っているのに文字起こしが無いセッションは、**次回起動時に自動で拾い直します。** アプリの終了やクラッシュで処理が流れても、やり直す必要はありません。

## 技術構成

| 役割 | 使用技術 |
|---|---|
| 音声取り込み | WASAPI（NAudio）。再生音はループバック、マイクは通常キャプチャ |
| 発話の切り出し | [silero VAD](https://github.com/snakers4/silero-vad) |
| 音声認識 | [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) + `moonshine-base-ja`（日本語専用） |
| UI | WPF + タスクトレイ常駐 |

### 設計上の判断

**録音中のリアルタイム文字起こしをやめました。**

当初は原作にならってストリーミング認識を載せていましたが、次の理由で削除しています。

- 日本語専用のストリーミングモデルが公開されておらず、多言語モデルを使わざるを得なかった
- その結果、不明瞭な音に対して別言語の文字（`那么` `嗯` `SELAMAT` など）を大量に出力した
- 画面が読めないうえ、「動作確認の指標」としても信用できなかった

計測したところ、**認識の処理時間は音声の長さの約 6%** でした。リアルタイムに縛られる必然性がないため、**録音中は音量インジケーターで取り込みを確認し、文字起こしは停止後に通しで行う** 構成に変更しています。

結果として、ストリーミング用の 324MB のモデルが不要になり、設定項目も 20 個以上から 13 個に減りました。

### モデルの選定

当初は 22 秒の音声 1 本で文字誤り率を測り、moonshine-base-ja を選びました。
ところが実際の会議（6 分、2 人）で使うと、**一言も話していない箇所に
読める日本語の文章が出る**という問題が出ました。短い音声では現れない壊れ方です。

そこで実会議の録音を素材に、同じ 77 区間で測り直しました。

| モデル | サイズ | 実時間比 | 無音に文章を作った数 |
|---|---|---|---|
| moonshine-base-ja | 135MB | 0.064 | 4 / 5 |
| whisper-large-v3-turbo (int8) | 1,036MB | 0.35 | 5 / 5 |
| qwen3-asr-0.6B (int8) | 987MB | 0.197 | 0 / 5 |
| **funasr-nano (int8)** | **963MB** | **0.151** | 4 / 5 |

判断は速度ではなく **壊れ方** で分けました。どれも 1 時間の会議を 10 分以内で
処理できるため、速度は選定の材料になりません。

- moonshine と whisper は「その日の見物人は、十二組あったので」「ご視聴ありがとうございました」のように、
  **読める日本語**を作ります。議事録に混ざると誤りだと気づけません。
- funasr-nano の失敗は「嗯」「the」で、**見た瞬間に誤りと分かります。**
- qwen3 は無音では完全に黙る代わりに、発話中に内部トークンを漏らして
  無関係な文章を生成する事故を起こしました（77 区間で 1 回）。無音の捏造より危険です。

内容の正確さも funasr-nano が最良で、moonshine で起きていた語尾切れ
（「おはようご」「パフォーマンス試験みた」）が解消しました。

無音の取りこぼしは、モデルではなく後述の無音ゲートで落としています。

別のモデルを試す場合は `scripts\download-offline-model.ps1 -Repository <リポジトリ>` で
差し替えられます。**最後に入れたモデルが使われます。**

なお FunASR Nano は `tokens.txt` を持たず、トークナイザーをフォルダごと渡す構成です。
モデル判定はファイル構成を見ているため、設定での指定は不要です。

### 無音に文章が出る問題

VAD は **確信度で発話を判定しており、音量を見ていません。** そのため
ほぼ無音の区間が発話として切り出され、そこにモデルが文章を作ってしまいます。

実会議で測ったところ、本当の発話は最小でも -46.6 dBFS、捏造が出た区間は
すべて -56 dBFS 以下で、間が 10 dB 以上空いていました。
そこで **-55 dBFS** を境に、文字起こしにかける前で落としています（`SilenceGateDbfs`）。

判定は区間全体の平均ではなく、**0.1 秒ごとに区切った中で一番大きい値**で行います。
平均で見ると、短い相づちが前後の無音に薄められて消えてしまうためです。

落とした区間はログに残ります。発言が 1 件消える処理なので、あとから理由を追えるようにしています。

```
[Info   ] 無音として除外しました: 00:01:55 (-93.3 dBFS)
```

### 無音時の扱い

WASAPI のループバックは **無音のあいだデータを返しません。** 取り込み側で実時間に合わせて無音を補わないと、録音の時間軸が音声とずれます。

一方、取り込みの揺らぎのたびに無音を挿し込むと発話が寸断されます。そのため「届いた音はその場で流し、実時間から 300ms 以上遅れたときだけ無音で埋める」方式にしています。
